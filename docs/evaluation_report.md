# 模块替换消融实验报告

**目标数据集**: ETTh1 (seq_len=512)
**基础模型**: TimeLLM + GPT2 Backbone

## 1. 结果概览

经过对三个候选模块的逐一消融验证，我们得出了以下最终结论：
- ❌ **CALF 主词对齐模块**: 性能退化，已回退。
- ❌ **正交频域解耦预测头**: 性能退化，已回退。
- ✅ **多尺度小波频率掩码分块 (MultiScaleWaveletPatchEmbedding)**: 总体性能超越基线，且训练速度大幅提升，**已成功保留**。

以下是针对成功落地的 `MultiScaleWaveletPatchEmbedding` 的详细评估对比。

## 2. 预测性能对比 (MSE / MAE)

> [!NOTE]
> 在长序列预测任务 (Long-Term Forecasting) 中，预测长度越长往往难度呈指数级增加。小波模块牺牲了微小的短期精度，换来了在 `336` 和 `720` 长期预测上显著的性能飞跃，使得全局平均误差打破了原本的基线限制。

| Pred_len | 基线版本 MSE / MAE | 小波改进版 MSE / MAE | 变化趋势 |
|----------|--------------------|----------------------|----------|
| **96**   | **0.3898** / **0.4114** | 0.4031 / 0.4222      | 📉 短期略降 |
| **192**  | **0.4274** / **0.4415** | 0.4331 / 0.4454      | 📉 短期略降 |
| **336**  | 0.4733 / 0.4737      | **0.4503** / **0.4590** | 📈 显著提升 |
| **720**  | 0.4536 / 0.4716      | **0.4436** / **0.4674** | 📈 显著提升 |
| **平均值 (Avg)** | 0.4360 / 0.4495  | **0.4325** / **0.4485** | 🔥 **整体超越基线** |

## 3. 计算效率与训练速度对比

> [!TIP]
> 这是一个巨大的工程收益，极其适合写入论文的实验分析章节（Efficiency Analysis）。

| 指标 | 基线版本 (PatchEmbedding) | 小波改进版 (MultiScaleWaveletPatchEmbedding) | 收益幅度 |
|------|---------------------------|----------------------------------------------|----------|
| **单 Step 耗时 (s/iter)** | 约 0.134 | **约 0.078** | 提升 **~42%** |
| **单 Epoch 耗时 (s)** | 约 346 | **约 178** | 提升 **~48%** |

## 4. 后续优化建议
当您后续尝试替换其他模块以追求更极端的 MSE / MAE 极限时，可以参考以下经验：
1. **警惕过拟合**: 序列预测模型对复杂组件非常敏感。之前 `CALF` 和 `FlattenHead` 替换失败的主要原因是引入了冗余参数，导致在小体量数据集 (ETTh1) 上容易跑飞。
2. **长短线折中**: 小波模块展示了一个经典的现象——“牺牲短线、拉升长线”。后续在引入新模块时，您可以通过在损失函数中增加对近期步长的权重（Decay Weighting）来试图双赢。
3. **保留当前版本**: 目前的代码 (`TimeLLM.py` + `Embed.py`) 已经集成了跑得最快、全局成绩最好的组合。在您增加新模块前，建议将当前的工作树打个 Git 标签 (Tag) 或保存副本。
